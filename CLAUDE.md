# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

```sh
npm run dev                              # http://localhost:3000 (service worker is off in dev; uses .next-dev/)
npm run build                            # next build (static export to out/) + scripts/precache.js
npm start                                # serve out/ locally
npm test                                 # node --test lib/
node --test lib/stats.test.js            # single test file
node --test --test-name-pattern="x" lib/ # single test by name
```

No linter is configured. Tests are plain `node:test` files next to the code in `lib/`; components are not tested.

## Architecture

Offline-first PWA with no backend: Next.js App Router as a **static export** (`output: 'export'`), JavaScript (not TypeScript), Tailwind v4 + shadcn/ui (`components/ui/`, config in `components.json`).

- **Data layer** — `lib/db.js` wraps IndexedDB (database `workouts`, stores `exercises`, `templates`, `sessions`). `lib/use-data.js` (`useData`) loads all three stores into React state; edits to existing records update state synchronously and write to IndexedDB in the background, new records trigger a reload to pick up their auto-increment id. Components get data and mutators from this hook rather than touching `db.js`.
- **Seeding via DB versions** — the exercise library (`lib/exercise-library.js`) and starter schedules (`lib/my-schedules.js`) are loaded in `onupgradeneeded`. To re-seed existing devices after editing them, bump the version in `indexedDB.open('workouts', N)` and add an `oldVersion < N` step. `db.js` is imported during the static build where `indexedDB` doesn't exist, so it opens lazily on first use — keep it that way.
- **Pure logic** in `lib/` (`stats.js`, `demo.js`, `swipe.js`, `dates.js`) is what's unit-tested; keep computations there rather than in components. Only ticked sets count toward stats. Demo data is generated by `demo.js` and removable without touching real data.
- **UI** — `app/page.js` is the single-page frame with tabs (Today, Schedules, Exercises, Progress); each screen is a component in `components/`.
- **Offline** — `public/sw.js` precaches everything listed in `out/precache.json`, which `scripts/precache.js` generates after `next build` (hence build = `next build && node scripts/precache.js`). Pages are network-first, hashed assets cache-first. Must be served from a domain root (`/` paths in the SW and manifest).
- **Backup** — all data is device-local; export/import JSON lives in the Exercises screen.
